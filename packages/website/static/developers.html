One fetch. Paid.

Wrap fetch with a session key. Any 402 under the key's cap settles in USDG and the response comes back. Over the cap, the call refuses before signing anything.

$ pnpm add @payhole/sdk

payholeFetch

import { payholeFetch, PaymentRefusedError } from "@payhole/sdk";

// A session key issued by the pocket owner, with its own cap and expiry.
const fetchPaid = payholeFetch({
  sessionKey: process.env.PAYHOLE_SESSION_KEY,
  budgetAccount: "0xYourBudgetAccount",
  maxAmount: 500_000n, // USDG base units, 6 decimals
});

try {
  const res = await fetchPaid("https://api.example.com/report", {
    method: "POST",
    body: JSON.stringify({ q: "usdg volume" }),
  });
  // 402, signed, settled, 200
  console.log(res.headers.get("payment-response"));
} catch (e) {
  if (e instanceof PaymentRefusedError) console.log(e.reason); // cap-exceeded
}

payhole CLI

# Create a key; the pocket owner registers it with a cap and expiry
$ payhole key create
created session key 0x9c1e…4a2f

# Cap, spend, remaining, balances
$ payhole status
key cap          0.12 USDG spent of 5 USDG
remaining        4.88 USDG

# Pay one URL, refusing anything above 0.05 USDG
$ payhole pay https://example.com/article --max 0.05
paid 0.02 USDG to 0xb9A6…B58f (x402 v2)
settled in 0x8e2c…91ab

x402 facts

What your server sends and what the pocket answers. No SDK is required on the server side. Any facilitator that speaks the standard exact scheme on Robinhood Chain settles it.
