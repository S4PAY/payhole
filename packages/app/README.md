# PayHole app

The phone side of PayHole. Version 0.1 does one thing: it puts the device's DNS behind an
encrypted connection to a resolver that drops drainers, phishing pages, and trackers. The pocket
(a USDG budget that pays over x402) and the operator marketplace come later and build on the same
app. The PayHole token never pays anyone, here or anywhere else in the project.

Bundle id `org.payhole.app` on both stores. Built with Expo SDK 57 and React Native, TypeScript
strict, a local Expo module for the native pieces, and Vitest for the pure logic.

## What the app does

| Tab | What is there |
| --- | --- |
| Home | One protection toggle with the vortex turning while the tunnel is up, 24-hour counters, a half-hour histogram of lookups and blocked answers, the last blocked names. |
| Resolver | The public PayHole resolver (`https://dns.payhole.org/dns-query`, `dns.payhole.org:853`) or a custom DoH URL and/or DoT host, with a one-query reachability check. |
| Lists | The two lists on the public resolver, license, and when each was last updated upstream (GitHub API, fails quietly offline). |
| About | How it works, what it does not do, what comes next, project links. |

### Android

`modules/payhole-dns/android` is a `VpnService` that only carries DNS. The device is handed
`10.111.222.2` as its DNS server and only that single address is routed into the tunnel, so all
other traffic keeps its normal path. Every UDP/53 query is parsed out of the IPv4 packet, sent to
the resolver over HTTPS (RFC 8484 POST) with DNS-over-TLS on 853 as the fallback, and written back
as a UDP reply. The service runs in the foreground with a notification and a "Turn off" action,
counts queries and blocked answers (an A record of `0.0.0.0` or an AAAA of `::`) into half-hour
slices covering the last 24 hours, and keeps those slices plus the last 20 blocked names in the
app's private preferences so they survive restarts and reboots. Nothing leaves the phone. The app
excludes itself from the tunnel so it can reach the resolver directly.

Not covered in 0.1: DNS over TCP/53, IPv6 transport for the queries themselves (the answers can
still carry AAAA records), and Android's own Private DNS setting, which should be off or set to
`dns.payhole.org` while the tunnel is on.

### iOS

`modules/payhole-dns/ios` uses `NEDNSSettingsManager` to install a DNS-over-HTTPS (or, when only a
host is given, DNS-over-TLS) setting for the whole device. iOS installs it disabled; the user turns
it on once under Settings, General, VPN, DNS & Device Management, DNS. The Home tab shows that step
and an "Open Settings" button until it is done. The system performs the lookups, so the app cannot
count them on iOS. This needs the `com.apple.developer.networking.networkextension` entitlement with
`dns-settings`, which `plugins/withPayholeDns.js` adds and which must also be enabled on the App ID
in the Apple Developer portal.

## Layout

```
app.config.ts          Expo config (name, ids, icons, fonts, plugins)
eas.json               EAS build profiles: development, preview (APK), production
plugins/withPayholeDns.js  iOS entitlement + Android permissions
modules/payhole-dns/   Local Expo module: TypeScript surface, Kotlin service, Swift module
src/App.tsx            Root, tab switching, splash handling
src/screens/           Home, Resolver, Lists, About
src/hooks/             useProtection (native state), useSettings (AsyncStorage)
src/native/dns.ts      Platform-neutral controller with an unsupported fallback
src/dns/               DNS wire helpers and the DoH probe (unit tested)
src/store/             Resolver settings parsing, validation, persistence (unit tested)
src/lists/             List sources and upstream freshness (unit tested)
assets/                Icon, adaptive icon, splash, fonts (OFL, see assets/fonts/LICENSE.md)
```

The `android/` and `ios/` folders are generated by `expo prebuild` and ignored by git.

## Working on it

```
pnpm install                          # from the repo root
pnpm --filter @payhole/app typecheck
pnpm --filter @payhole/app lint       # repo-wide ESLint config
pnpm --filter @payhole/app test       # Vitest, pure logic only
pnpm --filter @payhole/app start      # Metro; needs a development build, not Expo Go
```

Expo Go cannot run this app because the DNS module is native. Use a development build
(`eas build --profile development`) or a local `expo run:android` / `expo run:ios`.

## Building an Android APK locally

The build needs a JDK 17 and the Android SDK. Nothing here requires root: both install under the
home directory.

```
mkdir -p ~/.local/jdk ~/.local/android-sdk/cmdline-tools
curl -L -o /tmp/jdk17.tgz "https://api.adoptium.net/v3/binary/latest/17/ga/linux/x64/jdk/hotspot/normal/eclipse?project=jdk"
tar -xzf /tmp/jdk17.tgz -C ~/.local/jdk --strip-components=1
curl -L -o /tmp/cmdline-tools.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
unzip -q /tmp/cmdline-tools.zip -d ~/.local/android-sdk/cmdline-tools
mv ~/.local/android-sdk/cmdline-tools/cmdline-tools ~/.local/android-sdk/cmdline-tools/latest

export JAVA_HOME=~/.local/jdk
export ANDROID_HOME=~/.local/android-sdk
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
yes | sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" "ndk;27.1.12297006" "cmake;3.22.1"
```

Then, from `packages/app`:

```
pnpm exec expo prebuild --platform android --no-install
cd android && ./gradlew assembleRelease
```

The APK lands in `android/app/build/outputs/apk/release/app-release.apk`. Expo's template signs
it with the debug keystore, which is fine for side-loading onto a test phone (`adb install`) and
not for the Play Store. Keep the values above in step with `node_modules/react-native/gradle/libs.versions.toml`
when Expo is upgraded.

## Looking at a build before shipping it

`scripts/emulator-shots.sh <apk> <out-dir>` boots a headless emulator, installs the APK, and
writes screenshots of the Home tab, the Resolver check, and About into the output directory. It
needs the SDK `emulator` package, a system image, and an AVD called `payhole`
(`avdmanager create avd -n payhole -k "system-images;android-35;google_apis;x86_64" -d pixel_7`),
plus a user that may open `/dev/kvm`. A cold boot takes under a minute.

## Building with EAS

1. Create an Expo account and run `npx eas-cli login`, then `npx eas-cli init` in `packages/app`.
   It prints a project id; export it as `EAS_PROJECT_ID` (app.config.ts reads it) or add it to
   the environment of whichever machine runs builds.
2. `npx eas-cli build --profile preview --platform android` gives an installable APK.
3. iOS needs an Apple Developer membership. Add the Network Extensions capability with DNS Settings
   to the `org.payhole.app` App ID, then `npx eas-cli build --profile production --platform ios`
   and `npx eas-cli submit` for TestFlight.
4. Android release builds go through `npx eas-cli build --profile production --platform android`
   and a Google Play Console account for `org.payhole.app`.

Credentials for the stores stay off this repository and off developer machines; the same rule as
the GitHub and npm tokens on the box.

## Testing the tunnel by hand

With protection on, look up a name that the lists contain and one they do not:

```
adb shell "nslookup payhole.org"     # answers
```

On the Home tab the query counter moves and blocked names appear as the lists catch them. The
Resolver tab's check sends a single A query for `payhole.org` over HTTPS and shows the answer time.
